## 模块与数据归属

| 模块 | 职责与边界 |
|---|---|
| React 界面 | 浮窗、主窗口、输入、消息和历史；使用同一会话快照及增量事件，不直接操作 Pi |
| Go 会话服务 | 应用会话 ID、窗口当前会话、运行状态、待发送消息、恢复协调；按会话串行处理状态变化，不实现 Agent 循环 |
| Agent 适配层 | 一期 Pi RPC：启动/恢复、发送/停止、交互响应、模型和命令发现、事件转换；以能力声明表达差异，不提前实现通用插件平台 |
| 本地存储 | 应用拥有置顶、草稿、待发送状态和展示索引；Pi 拥有标题及供 Agent 恢复的原生会话数据，应用标题缓存只用于展示/搜索并可重建 |
| macOS 服务 | 快捷键、窗口与屏幕定位、托盘、通知、默认文件打开；已验证的原生桥接集中在此边界 |

一个执行中的会话对应一个 Pi 子进程；同一会话的两种窗口共享后端状态。隐藏窗口不影响进程。历史按需恢复，空闲进程可回收；回收前确认没有运行、交互等待或未处理的提交。回收超时与资源限制在测量后决定，不另行把参数交给用户逐项选择。

建议 Go 向 React 提供带版本的会话快照和有序事件：首次加载或窗口重连读取快照，之后接收增量；发现缺口重新读取。不要照搬原型的 400ms 全量轮询。

## 存储建议与恢复边界

建议 SQLite 保存应用元数据、草稿、待发送状态和可重建的消息展示/搜索索引，附件和 Pi 原生会话使用独立文件。SQLite 的本地事务、索引和结构迁移适合这里的应用状态存储，具体 Go 驱动在正式工程构建时验证并锁定，不增加数据库服务。依据：[SQLite 应用文件格式说明](https://www.sqlite.org/appfileformat.html)。

2026-09-11 标题边界替代原应用独立维护标题的方案：读取 Pi 标题和变更事件，手动改名通过 Agent 适配层调用 Pi；不自动命名，不自动向 Pi 写入应用旧标题。Pi 无标题时首条消息前 32 字仅作显示兜底。正式实现通过 Agent 的 SessionInfoReader 读取受管 Pi JSONL 文件中最后一条 session_info（含清空），启动时重建标题缓存；未落盘时禁用手动重命名。

Pi 原生会话是 Agent 续聊依据，应用展示缓存不能反向重建或改写 Agent 上下文。索引缺失时按应用登记的会话重建，不扫描或接管终端会话。应用元数据与 Pi 文件不是同一事务，恢复时必须对账，不能假设两者总是同时落盘。

已确认默认使用应用管理的工作目录并允许用户选择目录。工程上建议内部按会话组织默认子目录，持久保存实际路径；续聊沿用关联目录。此布局是工程建议，不再作为新的产品需求提问，也不表示权限隔离。用户选择的目录不能因元数据清理而被递归删除。应用托管目录仅在用户明确选择后删除，默认保留文件；后端校验所有权、路径和其他会话引用。

共享未发送草稿单独存储于 SQLite composer 表，不进入 sessions 历史。首次有效提交在同一事务内写入正式会话并删除对应草稿，保持原 ID 与双窗口引用；保存失败整体回滚。草稿采用版本校验，发送和草稿更新拒绝过期窗口写入；相同消息 ID 的重试仍幂等。

发送前记录消息 ID 和待发送状态；提交前标记投递中，收到 RPC 响应只标记 Agent 已接收，不标记任务完成。默认消息留在应用队列，当前运行 settled 后再交付；主动插入通过 steer，在同一会话调度中移出待发送队列，防止正常运行时双重提交。

若进程在写入 RPC 后、接收响应前退出，投递结果可能未知；RPC 请求 ID 不应被假定为跨重启幂等键。保留消息并明确中断/投递不确定，不自动重发，由用户决定继续或重试。未提交队列在重启后也暂停，遵循已确认的恢复规则。不承诺工具副作用恰好执行一次。

## 实施顺序与完成条件

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| 1：真实对话闭环 | 正式 Go/Wails/React 工程、Pi 适配、最小本地会话记录、双窗口文字对话 | 无需终端启动 Pi；流式消息同步；Esc 不停止任务；转入主窗口仍是同一会话；重启后可续聊；Pi 缺失与执行失败可见 |
| 2：状态与可靠性 | 多会话、队列与插入、停止、必要交互、超时换会话、异常恢复 | 并行会话隔离；正常投递不重复；模拟退出不自动重发；自动重试不被当成已完成；两窗口操作不会重复启动进程 |
| 3：完整交互 | 图片/文件、Agent 模型和命令菜单、历史管理、通知、目录与文件打开 | 覆盖需求 A10–A16；不暴露 thinking 和工具细节；历史只管理应用会话 |
| 4：桌面验收与打包 | 全屏/中文 IME/托盘退出/通知点击、构建目标统一、发布包 | 在声明支持的环境中逐项验收；明确最低 macOS 与 CPU 架构；完成目标分发方式所需的签名、公证验证 |

第一阶段优先使用合成模型夹具驱动真实 Pi 做可重复集成测试；实际已配置模型的端到端体验另行验收，不将模拟服务测试当成真实提供商验证。现有 17 项 Pi 协议断言作为基线复用，增加正式 Go 适配和重启恢复的测试，而不是反复验证已通过的同一事实。

全屏、中文输入法、托盘完整退出流程和通知点击目前仍未验收。全屏与输入法属于交互路线风险，应在第一阶段随真实输入界面尽早检查；通知点击随通知功能完成，不为缺少该功能而阻塞文字闭环。

## 范围控制

原型分支保留验证证据，正式代码按上述边界重建；复用已验证的窗口配置与定位逻辑，不整批合并模拟任务和轮询代码。暂不引入远程服务、独立常驻守护进程、通用插件框架或第二个 Agent 实现。

签名账号、对外分发范围等必须依赖用户资源的决策，在打包阶段集中处理。目录名称、表结构、回收参数等由工程方案承担，只有发现影响既定产品行为的新取舍时再询问用户。


## 2026-09-11 正式实现

- `internal/core/process.go` 将工具事件投影为绑定用户消息的步骤，保留状态与接收时间，恢复时将未结束步骤标为中断；前端只合并连续同类动作，可展开对象，最终回复后收起。
- `internal/agent/pi/title.go` 读取受管会话标题；`internal/core/title.go` 统一 Pi 标题来源，手动改名调用 `set_session_name`，旧 RPC 状态不能覆盖更新的标题事件。旧应用标题不写回 Pi。
- `internal/core/selection.go` 在同一事务内保存独立会话、首条消息与浮窗选择，再提交 Agent；不触碰共享 composer。模板单次替换并使用点击时的时间快照。
- `selection_darwin.go/.m` 实现 AX 标准选区及网页 text-marker 选区、非激活工具条、系统语言识别和权限入口；异步串行取词、过期结果作废。点击复用已有浮窗展示函数，跳过普通唤起的超时换会话规则。没有剪贴板/OCR 等替代路径。
- 设置页支持总开关、按钮增删与排序、恢复默认、变量插入和未知变量提示。默认翻译规则仅用于未修改的默认翻译模板，自定义模板完全按用户内容发送。

验证：`sh scripts/test.sh` 包含前端测试、构建及 Go race/行为测试；`sh scripts/build-app.sh` 生成本机签名应用。实际跨应用、跨屏、全屏取词由用户在此应用上验收，本轮不启动桌面自动验收干扰用户。

### 启动交互异常回归（2026-09-11）

用户报告打开后卡死。隔离启动采样未见主线程阻塞，但将鼠标点击交给正式划词监听器，稳定触发 `NSInternalInconsistencyException`：监听器在判断事件类型前读取 `keyCode`，AppKit 不允许在鼠标事件上读取键盘属性。调整为先判断键盘事件再读取按键码，原复现转为通过。

新增 `scripts/check-selection-events.sh`，直接编译正式 `selection_darwin.m` 并向本地 AppKit 分发点击、抬起、右键和 Esc；不向系统注入输入、不读取用户数据。已接入 `scripts/test.sh`，补上此前纯 Go/前端测试未覆盖的原生事件监听路径。

### 划词全应用无响应排查（2026-09-11）

正式进程快照 `selectionPermission=false`，系统辅助功能列表中旧 Pi Popchat 条目为开启状态；取词入口因此在权限检查处返回，尚不能据此判断飞书/浏览器/Codex/Cursor 的 AX 兼容性。当前包及两个旧包的 designated requirement 均为不同的 cdhash，当前机器无可用代码签名证书；临时签名重建后旧授权不一定适用于当前进程。系统授权数据库不可读取，未改写数据库或代替用户授予权限。

已修复授权入口：即使 TCC 不再弹提示，也直接打开“隐私与安全性 → 辅助功能”。主窗口明确显示权限阻断；授权状态改变后重新注册全局监听并通知前端刷新。前端权限状态回归、Go 测试和原生输入事件回归通过，新包已启动，系统权限页已定位。需要重新将当前构建加入系统授权；获得有效授权前，跨应用取词仍未验收通过。


### 授权开启仍被拒绝的确证（2026-09-11）

系统 `tccd` 日志明确记录 `Failed to match existing code requirement for subject app.pi-popchat.desktop and service kTCCServiceAccessibility`，并显示旧/当前不同的 cdhash；重启同一构建后仍重复此拒绝。此前将“系统开关开启”视为当前构建已授权的假设不成立。处理应是只重新关联该应用的有效授权，不能继续要求用户机械切换开关，也不应靠改写 TCC 数据库或放宽签名要求绕过校验。

打包脚本增加可选 `PI_POPCHAT_SIGN_IDENTITY`，供使用固定签名证书的持续构建；保留临时签名默认值并明确提示其授权失效风险。本次排障不重建正在重新授权的包，以免再次改变签名。实际取词链路必须在 `AXIsProcessTrusted()` 为真后继续验证。

授权处理结果：用户完成系统 Touch ID 确认后，仅移除 Pi Popchat 旧条目并重新添加 dist 中同一应用；正式进程界面已显示“辅助功能权限已开启”，后续 tccd 日志无签名不匹配。未重新构建当前包。独立网页/原生窗口能建立选区，但测试期间前台窗口发生变化，不能将该自动化结果作为工具条实际显示通过；临时验证窗口和网页已清理。

### 固定本机签名与工具条窗口圆角（2026-09-11）

本机创建专属自签名代码签名证书，私钥存入登录钥匙串，仅为代码签名设置信任，证书有效期至 2036-09-08；临时导入文件中的私钥与 PKCS#12 已删除。构建读取 `~/Library/Application Support/Pi Popchat/build-signing-identity` 中的证书 SHA-1；显式 `PI_POPCHAT_SIGN_IDENTITY` 优先。配置存在但证书不可用时不回退临时签名。此证书用于本机开发，不等同于 Developer ID 或 Apple 公证；切换签名身份后需重新授权一次。证书和私钥应长期保留，不能随构建重新生成。

真实窗口含阴影截图复现白色矩形轮廓：仅设置 CALayer.cornerRadius 未约束 behind-window material 的系统合成轮廓。对 NSVisualEffectView 配置可拉伸圆角 maskImage 后轮廓消失。另修正设置 contentView 时新视图被旧窗口尺寸覆盖的问题。`sh scripts/check-selection-appearance.sh` 使用合成按钮展示正式窗口路径，检查完整高度并从含阴影截图验证圆角外不存在白线；需要截图权限和 Python Pillow，桌面验收串行运行。之前只渲染组件、或截图排除窗口阴影，均无法捕获该问题。

验证结果：两次包含不同本机二进制内容的构建，designated requirement 均为应用标识加同一证书 leaf 指纹；使用 `codesign --verify --deep --strict -R` 交叉验证通过。用户完成钥匙串「始终允许」后第三次签名无弹窗完成。当前 dist 已替换为修复版，并通过系统设置移除旧签名条目、添加当前固定证书应用，正式进程显示「辅助功能权限已开启」。本轮验证了跨构建身份一致及当前授权，未把它夸大为所有未来升级的系统行为保证。完整测试与含阴影原生截图回归通过。

### 回答图片展示（2026-09-11）

MessageView 不再将 Markdown 图片替换为文字；MessageImage 负责网络/内嵌图片、异步本地读取、失败重试和打开原图。主窗与浮窗限制图片尺寸。类型化 ReadMessageImage 接口绑定 sessionId，os.OpenRoot 限制自动读取在会话目录内，识别内容 MIME、限制 16 MB、非阻塞打开后拒绝特殊文件；不向网页暴露任意本地文件服务。Pi 原始工具图片块的导入不在本次 Markdown 渲染变更中。

验证使用合成 PNG 和本地 HTTP 页面：真实页面图片和失败提示显示通过；新增测试覆盖 Markdown 图片渲染、原图入口、重试、危险协议、切换会话时旧读取结果不覆盖新图片，以及本地路径/符号链接越界、假图片、超限文件、FIFO 和不存在的会话。旧独立验收测试保留 HTML/危险链接断言，将远程图片断言按用户新需求改为显示且不发送 referrer。

图片版已用同一固定证书打包并替换 dist。升级后正式应用设置仍显示「辅助功能权限已开启」，全程未修改系统权限；本次形成了实际跨版本升级保留授权的验证证据。合成图片浏览器页及临时 HTTP 服务已清理。
