# 一期架构与实施计划

日期：2026-09-09。状态：方案已落实为一期工程，执行结果见 delivery-report.md。已确认决策以 requirements.md 和 technology-selection.md 为准；本计划不将工程建议伪装为用户确认。

## 下一步的交付目标

停止逐项访谈实现细节。先连接已经分别验证的桌面壳和 Pi RPC，交付第一条真实可用链路：快捷键唤起 → 发送文字 → Pi 流式回复 → 在主窗口查看同一会话 → 应用重启后续聊。这是一期首个里程碑，不缩减已确认的一期范围。

## 模块与数据归属

| 模块 | 职责与边界 |
|---|---|
| React 界面 | 浮窗、主窗口、输入、消息和历史；使用同一会话快照及增量事件，不直接操作 Pi |
| Go 会话服务 | 应用会话 ID、窗口当前会话、运行状态、待发送消息、恢复协调；按会话串行处理状态变化，不实现 Agent 循环 |
| Agent 适配层 | 一期 Pi RPC：启动/恢复、发送/停止、交互响应、模型和命令发现、事件转换；以能力声明表达差异，不提前实现通用插件平台 |
| 本地存储 | 应用拥有标题、置顶、草稿、待发送状态和展示索引；Pi 拥有供 Agent 恢复的原生会话数据 |
| macOS 服务 | 快捷键、窗口与屏幕定位、托盘、通知、默认文件打开；已验证的原生桥接集中在此边界 |

一个执行中的会话对应一个 Pi 子进程；同一会话的两种窗口共享后端状态。隐藏窗口不影响进程。历史按需恢复，空闲进程可回收；回收前确认没有运行、交互等待或未处理的提交。回收超时与资源限制在测量后决定，不另行把参数交给用户逐项选择。

建议 Go 向 React 提供带版本的会话快照和有序事件：首次加载或窗口重连读取快照，之后接收增量；发现缺口重新读取。不要照搬原型的 400ms 全量轮询。

## 存储建议与恢复边界

建议 SQLite 保存应用元数据、草稿、待发送状态和可重建的消息展示/搜索索引，附件和 Pi 原生会话使用独立文件。SQLite 的本地事务、索引和结构迁移适合这里的应用状态存储，具体 Go 驱动在正式工程构建时验证并锁定，不增加数据库服务。依据：[SQLite 应用文件格式说明](https://www.sqlite.org/appfileformat.html)。

Pi 原生会话是 Agent 续聊依据，应用展示缓存不能反向重建或改写 Agent 上下文。索引缺失时按应用登记的会话重建，不扫描或接管终端会话。应用元数据与 Pi 文件不是同一事务，恢复时必须对账，不能假设两者总是同时落盘。

已确认默认使用应用管理的工作目录并允许用户选择目录。工程上建议内部按会话组织默认子目录，持久保存实际路径；续聊沿用关联目录。此布局是工程建议，不再作为新的产品需求提问，也不表示权限隔离。用户选择的目录和任务产物不能因元数据清理而被递归删除。

发送前记录消息 ID 和待发送状态；提交前标记投递中，收到 RPC 响应只标记 Agent 已接收，不标记任务完成。默认消息留在应用队列，当前运行 settled 后再交付；主动插入通过 steer，在同一会话调度中移出待发送队列，防止正常运行时双重提交。

若进程在写入 RPC 后、接收响应前退出，投递结果可能未知；RPC 请求 ID 不应被假定为跨重启幂等键。保留消息并明确中断/投递不确定，不自动重发，由用户决定继续或重试。未提交队列在重启后也暂停，遵循已确认的恢复规则。不承诺工具副作用恰好执行一次。

## 实施顺序与完成条件

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| 1：真实对话闭环 | 正式 Go/Wails/React 工程、Pi 适配、最小本地会话记录、双窗口文字对话 | 无需终端启动 Pi；流式消息同步；Esc 不停止任务；转入主窗口仍是同一会话；重启后可续聊；Pi 缺失与执行失败可见 |
| 2：状态与可靠性 | 多会话、队列与插入、停止、必要交互、超时换会话、异常恢复 | 并行会话隔离；正常投递不重复；模拟退出不自动重发；自动重试不被当成已完成；两窗口操作不会重复启动进程 |
| 3：完整交互 | 图片/文件、Agent 模型和命令菜单、历史管理、通知、目录与文件打开 | 覆盖需求 A10–A16；不暴露 thinking 和工具细节；历史只管理应用会话 |
| 4：桌面验收与打包 | 全屏/中文 IME/托盘退出/通知点击、构建目标统一、发布包 | 在声明支持的环境中逐项验收；明确最低 macOS 与 CPU 架构；完成目标分发方式所需的签名、公证验证 |

第一阶段优先使用合成模型夹具驱动真实 Pi 做可重复集成测试；实际已配置模型的端到端体验另行验收，不将模拟服务测试当成真实提供商验证。现有 17 项 Pi 协议断言作为基线复用，增加正式 Go 适配和重启恢复的测试，而不是反复验证已通过的同一事实。

全屏、中文输入法、托盘完整退出流程和通知点击目前仍未验收。全屏与输入法属于交互路线风险，应在第一阶段随真实输入界面尽早检查；通知点击随通知功能完成，不为缺少该功能而阻塞文字闭环。

## 范围控制

原型分支保留验证证据，正式代码按上述边界重建；复用已验证的窗口配置与定位逻辑，不整批合并模拟任务和轮询代码。暂不引入远程服务、独立常驻守护进程、通用插件框架或第二个 Agent 实现。

签名账号、对外分发范围等必须依赖用户资源的决策，在打包阶段集中处理。目录名称、表结构、回收参数等由工程方案承担，只有发现影响既定产品行为的新取舍时再询问用户。
