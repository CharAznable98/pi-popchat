# pi-popchat 一期需求文档

版本：0.1 · 日期：2026-09-09 · 状态：需求访谈已达成共同理解，技术选型未定。

本文中的“必须”为已经确认的产品需求。“兼容性约束”为 Pi 0.84.1 实测结果对实现的限制。“待定”不属于已确认决策，不应在实现时悄然固化。

## 1. 产品定位与边界

pi-popchat 是面向 macOS 的桌面 Agent 客户端。用户通过全局快捷键进入临时浮窗交流，也可以在正式主窗口中查看、管理和继续历史会话。

产品价值是桌面交互体验、会话管理和成熟 Agent 的接入，不按具体业务场景设计工作流，不重写 Agent 的规划、工具执行或模型调用能力。

关系为 **应用 → Agent → 模型**。一期仅支持 Pi；架构需为后续接入 Codex、Claude Code 保留边界，但不在一期实现这些接入，也不提前承诺所有 Agent 能力完全一致。

| 范围 | 一期要求 |
|---|---|
| 平台 | 仅 macOS；最低系统版本及 Intel 支持待技术选型决定 |
| Agent | Pi；应用自动管理其后台进程，日常使用无需打开终端或手动启动 Pi |
| 安装与配置 | 不安装 Agent；检测缺失或配置不完整时提供安装/配置指引及重新检测入口 |
| 模型与认证 | 不直接对接模型、不管理凭证；模型列表和切换只使用 Agent 暴露的能力 |
| 现有资源 | 复用用户 Pi 配置、认证、模型、扩展和 Skills；受 RPC 兼容性限制 |
| 会话范围 | 只管理应用自身创建的会话，不导入或接管终端会话 |

## 2. 窗口与应用生命周期

### 2.1 浮窗

| 操作或状态 | 必须表现 |
|---|---|
| 全局快捷键 | 默认 `⌥Space`，可修改；冲突时提示重新设置 |
| 唤起 | 打开可输入的 Agent 对话浮窗，无需先打开主窗口或终端 |
| 置顶 | 浮窗保持在其他普通窗口上方 |
| 按 Esc | 收起浮窗，不停止或取消 Agent 执行 |
| 点击浮窗外部 | 只转移焦点，不隐藏浮窗，也不影响执行 |
| 停止任务 | 使用独立停止操作，不与隐藏窗口绑定 |
| 转入主窗口 | “在主窗口中打开”定位同一会话并收起浮窗，消息与执行连续 |

多显示器唤起以当前活动窗口所在屏幕为准，不跟随鼠标。每次唤起前确定目标屏幕，并在该屏可用区域居中。窗口跨屏时按主要占用的屏幕定位；浮窗已在别屏可见时移动过来，同屏再次按快捷键时收起。该规则已通过原型验证，并于 2026-09-09 获得用户实际多显示器体验确认。

尺寸、位置记忆及全屏 Space 行为仍待设计，不把“置顶”扩大解释为覆盖所有系统界面。

### 2.2 主窗口与驻留

关闭主窗口或浮窗不等于退出应用。应用继续在菜单栏驻留，全局快捷键及后台任务继续有效。

用户主动选择“退出”才真正退出。仍有任务执行时先提示，允许取消退出或继续退出。退出后保留已落盘历史；不承诺中断的工具执行能从原位置自动恢复。

### 2.3 浮窗会话超时规则

“临时”指入口和窗口形态，不代表会话不保存。

| 再次唤起时的情况 | 默认打开 |
|---|---|
| 尚无浮窗会话 | 新会话 |
| 距最近一次隐藏未超过 30 分钟 | 原浮窗会话，包括草稿和已有状态 |
| 已超过 30 分钟，原会话未执行且未等待回答 | 新会话 |
| 原会话仍在执行或等待用户回答 | 原会话，即使超过 30 分钟 |

计时起点为最近一次隐藏浮窗。点击外部不会隐藏，因此不会启动这次计时。阈值一期默认 30 分钟；是否提供用户配置入口待定。

超时新建不删除、不关闭旧会话，旧会话可以随时从主窗口找到并继续。这里的新建只改变浮窗当前会话。

浮窗和主窗口分别记住自己的当前会话。主窗口浏览或切换历史不会自动改变浮窗会话。二者若展示同一会话，应看到同一份消息和执行状态，不能创建副本。

## 3. 对话输入、展示与运行

### 3.1 输入

一期必须支持文字、粘贴图片和拖入文件。附件在发送前可辨识，不能将“接收附件”暗示为所有 Agent 都能理解所有格式。

输入框支持 `/` 菜单，展示、搜索并调用 Agent 暴露的 Skills、提示词模板、扩展命令。应用不维护另一套业务命令体系。Agent 未暴露的终端内置命令不能假装可执行。

提供 Agent 支持的模型选择与切换；候选列表和执行结果均来自 Agent，客户端不自行请求模型服务。

语音输入本期不做，后续单独评估。

### 3.2 输出和必要交互

| 输出类别 | 展示原则 |
|---|---|
| Agent 回复 | 流式展示，支持回复所需的常规文本格式和可打开的文件链接 |
| 执行过程 | 简短状态，例如“正在处理”“正在重试” |
| 原始 thinking | 不展示 |
| 工具参数、工具输出和执行日志 | 不展示，不提供工具详情展开 |
| 明确的选择、确认、输入请求 | 展示可操作的问题，并将用户结果交回 Agent |
| 失败或停止 | 明确表达状态，不能显示为任务成功完成 |

不增加模型调用来猜测执行进度、总结工具日志或判断回复是否在提问。普通文本提问直接作为回复展示，只有明确交互请求进入“等待回答”状态。

### 3.3 并发与执行中的新消息

允许多个会话同时执行。用户切换或隐藏窗口不会中止任何任务。主窗口标识执行中和等待回答的会话。

执行中发送的新消息默认进入待发送队列。用户可对待发送消息选择“立即插入”，客户端需说明实际接收时机是当前步骤结束后，不能承诺强行抢占正在执行的工具。

兼容性约束：Pi 0.84.1 有 `follow_up` 和 `steer`，但 RPC 没有撤回单条消息或原子转换队列类型的接口。实现应由应用保留尚未提交的队列：默认等待当前执行结束后提交，插入时移出本地队列并调用 `steer`。这属于交互消息调度，不是重新实现 Agent 循环。

消息提交确认、失败重试、重复投递防护、跨重启草稿/队列持久化及同一会话双窗口输入的协调细节待技术设计确定。不得静默丢失或重复发送消息。

## 4. 历史、目录与文件

### 4.1 历史管理

主窗口管理应用创建的所有会话，支持搜索、重命名、置顶、删除和继续对话。默认按最近活跃时间排序，置顶会话有明确展示位置。

搜索的标题/正文范围、删除确认及恢复策略、执行中会话能否删除待设计。文件夹、标签、会话分支管理不进入一期。

### 4.2 工作目录

默认采用应用管理的工作目录，并提供选择已有文件夹的能力。每个会话与其工作目录的关系应持久记录，以便续聊使用正确位置。

“每会话独立子目录”是建议，尚未单独确认；共享目录或独立目录的具体布局待技术设计。选择目录不是权限隔离，也不能被描述成沙箱。

普通文件需要交给 Agent 的可访问路径；Agent 是否有能力处理格式由其工具和 Skills 决定。图片可以使用 Pi 的原生图片输入。

### 4.3 文件打开

对话里的有效本地文件链接使用 macOS 默认应用打开，同时提供“在 Finder 中显示”。不做内置文件编辑器。

不假设 Agent 会发送统一的产物列表。回复文件链接的解析、相对路径基准、附件持久化及删除会话是否保留产物待设计。

## 5. 通知

浮窗隐藏期间，任务完成或需要用户回答时发送 macOS 通知。通知本身不自动弹出浮窗或抢焦点；用户点击通知时恢复对应会话。

多个会话并行时，通知必须定位到触发事件的会话，而非当前浮窗或主窗口随意选中的会话。失败通知的具体文案和规则、主窗口正在查看同一会话时是否抑制通知待设计。

Pi 的 `prompt.success` 仅表示接收；`agent_end` 之后可能继续自动重试；`agent_settled` 才表示执行停止自动继续。客户端必须结合错误和停止原因判断实际结果，不能把 settled 一律当成业务成功。

## 6. Pi 兼容性基线

基线为本机 **Pi 0.84.1**。已通过真实 Pi 进程、本地模拟模型服务完成 17 项协议断言，详见 [验证报告](pi-compatibility-report.md)。

基础 RPC 对话、图片、工具生命周期、选择/确认/输入请求、模型切换、资源命令、多进程会话隔离、重启续聊和重试/错误均已验证。普通文件使用路径交接，排队转插入采用客户端待发送队列。

Pi 的 TUI 自定义组件 `custom()` 无法在 RPC 中使用。复用用户扩展必须尊重这个边界，不承诺所有扩展自动兼容。真实模型服务、所有文件格式及全部第三方扩展不在此次测试覆盖内。

## 7. 验收场景

| ID | 场景 | 验收结果 |
|---|---|---|
| A01 | 已配置 Pi，未打开终端，按唤起快捷键 | 可进入对话；应用自行启动所需 Pi 进程 |
| A02 | Pi 缺失或未配置 | 显示可执行的安装/配置引导；不代装、不提取凭证 |
| A03 | 修改全局快捷键或发生冲突 | 修改成功或收到明确冲突提示 |
| A04 | 执行中按 Esc | 浮窗隐藏，任务继续 |
| A05 | 点击浮窗外部 | 浮窗保持显示，任务继续 |
| A06 | 隐藏后在阈值内或阈值外唤起 | 按第 2.3 节规则恢复或新建；旧会话仍能继续 |
| A07 | 主窗口切换历史 | 不改变浮窗当前会话 |
| A08 | 浮窗转入主窗口 | 定位同一会话，收起浮窗，不打断任务 |
| A09 | 多会话同时执行 | 状态和消息互不混淆；切换不终止任务 |
| A10 | 执行中发送并插入消息 | 默认排队；主动插入在 Agent 可接受时机交付，无重复 |
| A11 | 粘贴图片、拖入文件、使用 `/` 菜单 | 图片/文件正确交接；菜单来自 Agent 暴露资源 |
| A12 | Agent 请求用户选择或输入 | 可在应用中完成；答案返回正确会话与请求 |
| A13 | Agent 执行工具 | 用户只看到简短状态，不出现原始参数、thinking 或工具日志 |
| A14 | 隐藏期间完成或等待回答 | 通知不抢焦点；点击定位正确会话 |
| A15 | 历史会话管理 | 可搜索、重命名、置顶、删除和续聊；不包含终端会话 |
| A16 | 选择目录后续聊，打开产物 | 使用关联目录；文件以默认应用打开或在 Finder 定位 |
| A17 | 关闭主窗口 | 菜单栏、快捷键和后台执行继续工作 |
| A18 | 有任务时主动退出 | 先提示；可取消或继续；已落盘历史保留 |
| A19 | Pi 自动重试或最终失败 | 不提前通知成功，不把接收成功或执行停止当成任务成功 |

## 8. 后续决策范围

已选择 Go + Wails v3 + React，并完成首轮桌面原型。技术设计仍需解决 Pi 进程接入、版本兼容、应用会话索引、文件目录组织及安装包分发；桌面行为的未覆盖项见技术选型记录。

后续 UI 设计应补齐全屏 Space/特殊窗口焦点行为、窗口尺寸、输入快捷键、搜索范围和删除流程等细节；性能指标需通过原型测量后设置，不能凭空承诺内存或唤起耗时。

不再引入按行业/任务类型定制的工作流、Agent 自研、模型网关、凭证系统、终端会话接管、语音或文件编辑器。
