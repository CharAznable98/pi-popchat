# 一期架构独立评审与验收矩阵

评审日期：2026-09-09。评审者：独立 architecture_review subagent。输入为 requirements.md、implementation-plan.md、technology-selection.md、pi-compatibility-report.md、desktop-probe-report.md。此次只评审设计，未将尚不存在的产品代码或原型结论视为正式产品验收。

## 结论

现有 Go + Wails v3 + React、每个运行会话一个 Pi RPC 进程、应用持有待发送队列的方向合理。五个职责边界足够，不需要远程服务、Node 中间层、独立守护进程、事件总线框架或通用插件平台。可以直接实施，但下列正确性条件必须进入实现和独立验收；其中投递恢复、双窗口一致性和完成状态判断属于发布阻塞项。

## 必须落实的五项约束

1. **执行停止与业务成功分开。** prompt 响应仅为接收，agent_end 可能紧接重试。队列正常推进以 agent_settled 为边界，同时结合本轮最后的 error/abort 状态；新的运行必须清除上一轮错误，不可因旧消息错误把后续成功误判为失败。收到 settled 不证明业务目标达到，只能表达执行完成。
2. **投递未知必须可见且不自动重发。** 应用数据库与 Pi JSONL 不能跨文件原子提交。发送意图必须先持久化，再写 stdin；在任意中途崩溃都不得把消息重新自动排入运行队列。客户端消息 ID 能防界面重复提交，不能当作 Pi 跨重启幂等键。
3. **同一会话所有状态变化串行化。** 两窗口共享会话状态、运行进程和待发送队列；发送、插入、停止、交互回答、退出及 Pi 事件在同一会话调度序列中处理。进程创建需要单次初始化保护；不能先解锁、启动进程、再登记而导致双启动。
4. **超时只在再次唤起时决定。** 所有隐藏入口记录最近隐藏时间；点击外部不记录。超过 30 分钟且原会话既不执行也不等待回答才换新会话，旧任务和历史不受影响。等于 30 分钟仍恢复原会话。不得由后台定时器主动改当前会话。
5. **桌面和退出能力需要正式应用证据。** 原型多屏确认可复用思路，不能代替正式构建的全屏、中文 IME、菜单栏关闭/恢复、通知点击和退出验收。Pi 退出后清理 stdout/stdin 读取协程、请求等待者和扩展交互；应用退出不得遗留由自己启动的 Agent 进程。

## 建议的最小模块接口

| 边界 | 应当拥有 | 不应拥有 |
|---|---|---|
| app/session 服务 | 会话 ID、消息提交 ID、运行状态、队列、交互请求、窗口选中会话、恢复策略 | Pi JSONL 细节、工具规划 |
| agent/pi 适配 | 可执行文件发现、RPC 请求匹配、事件解码、Pi 会话路径、能力发现、进程生命周期 | 历史置顶、窗口显示策略、通知抑制 |
| store | SQLite 事务、迁移、应用会话登记、草稿、投递意图、展示索引 | Agent 上下文编辑、扫描终端会话 |
| desktop | 两窗口、快捷键、选屏、通知、目录选择、文件打开、退出提示 | 对话业务状态的副本 |
| frontend | 会话快照渲染、输入、附件预览、菜单和明确交互卡片 | 直接调用模型、凭证、独立运行队列 |

适配接口只覆盖本期已使用操作：Start/Resume、Prompt、Steer、Abort、RespondInteraction、Models/SetModel、Commands、Events、Close。允许 Pi 适配自行保留具体字段，不必为了未来 Agent 把所有消息压成一个过宽的通用字典。各操作都需明确错误和取消语义。所有 RPC 请求带 ID，未知事件容忍但未知响应错误可见；stderr 保留有界诊断，不混入用户聊天。

Go 的普通锁加按会话串行操作即可，不强制实现 actor 框架。需避免持锁等待 RPC 响应：事件读取循环可能需要同一把锁，否则会死锁。可用每会话命令队列，或者短临界区标记意图、异步 I/O、回到会话调度落结果。标准库进程管理足够。

## 状态、队列与异常恢复

运行状态建议只使用 idle、starting、running、retrying、waiting_input、stopping、interrupted、failed；“完成”可以是当前轮结果，而不额外制造永久终态。等待交互不代表进程不运行，不能回收。模型切换执行结果来自 Pi；运行期间若 Pi 不允许切换，显示明确原因，不假装客户端切换成功。

每条提交有稳定 clientMessageID 和状态：queued → dispatching → accepted；失败可进入 rejected，异常不确定进入 uncertain。accepted 表示 Pi 接收，不代表模型已看到，也不代表工具已完成。UI 队列移除和 dispatching 落盘应处于一次数据库事务。点击插入与正常 settled 出队竞争时，只能有一个取得这条消息。已 dispatching/accepted 不再显示可撤回或可再次插入。

| 故障点 | 重启行为 | 可接受的展示 |
|---|---|---|
| queued 已保存但未写 stdin | 暂停，不自动发送 | 待发送，因上次退出已暂停；用户可明确发送 |
| dispatching 已保存，stdin 写前或写后崩溃 | 不自动发送；读取已登记 Pi 会话对账 | 已中断，投递结果不确定；不得声称肯定没执行 |
| 收到 accepted 后 Pi/应用崩溃 | 加载 Pi 已落盘历史，不自动续执行 | 上次任务已中断；可继续对话 |
| Pi 已保存回复，应用展示索引未落盘 | 从 Pi 会话重建展示索引 | 已保存回复仍可见；不生成重复消息 |
| 用户主动停止 | 发 abort，等待终止结果；队列暂停 | 已停止，未发队列保留，避免刚停止又启动下一条 |

继续与重试的文案要区分：继续是在现有历史上发送新的用户指令，不能描述成恢复工具指令指针。插入消息可能在 Pi 内部等待后续步骤，崩溃后仍适用中断规则。运行失败后推荐暂停剩余本地队列，避免缺少前置结果时连续执行。

进程按需启动并复用 Pi 配置，但会话文件必须放应用登记目录。启动前读取版本，兼容提示基于已测 0.84.1，不能把未来版本一律阻止也不能宣称均兼容。macOS 从 Finder 启动的 PATH 常不含 nvm，需支持合理路径发现/用户指定 Pi 可执行文件，并测试无 shell 初始化的启动方式。不要为找到 Pi 而修改用户 shell 配置。

## 双窗口、事件与草稿

mainSessionID 与 overlaySessionID 分开保存。转入主窗口只把 mainSessionID 设为浮窗当前 ID，再隐藏浮窗；浏览历史不写 overlaySessionID。通知点击显式携带目标会话 ID，不能读取当前选中 ID 代替。删除目标已不存在时，通知点击回到主窗口并提示，不创建同名空白会话。

会话快照带 revision，事件带 sessionID 和递增 revision。前端先订阅再取快照，忽略不高于快照 revision 的事件；出现缺口重新拉取。不要在每个流式 token 都写 SQLite，可内存合并，message_end 或有界间隔持久化，Pi 原始日志用于恢复；不能通过 400ms 全量轮询实现产品同步。

建议草稿以会话共享，更新携带 draftRevision；遇到另一个窗口更新时保留本地未提交内容并明确冲突，不用最后写入静默覆盖。发送时提交具体文本与稳定 ID，服务端仅在草稿 revision 匹配时清空对应草稿，避免清空另一个窗口刚输入的新内容。若实施成本受限，也可以持久化每窗口每会话草稿，但必须明确显示各自草稿，而非让用户误以为同步失败。

## 本地数据、附件和展示

SQLite 维护应用登记会话以及可重建索引；Pi 原生文件仍是续聊上下文来源。正文搜索仅索引用户消息和最终可见回复，不把 thinking/工具日志加入搜索结果。删除会话建议明确确认，执行/等待中的会话先要求停止；删除元数据及应用会话记录，不递归删除用户选择目录或任务产物。遇到 Pi 文件缺失要显示不可恢复原因，不悄悄启动空白 Agent 冒充续聊。

文件拖入和图片粘贴需先复制到应用管理附件路径并持久化，后发送；原文件移走不应破坏已保存输入。路径用结构化字段或安全转义交给 Pi，不经 shell 拼接执行。Markdown 默认禁用原始 HTML；链接点击仅允许明确的 web/local-file 方案，不允许任意 scheme 执行。相对文件链接基于会话工作目录解析，存在才提供打开或 Finder 定位，不能暴露工具日志作为替代。使用图片原生输入与文件路径交接两条通路，UI 不宣称全格式理解。

| A13 | 真实 Pi 执行只读工具，夹具含 thinking/工具敏感标记 | 仅简短状态和可见回复；DOM、搜索、历史不出现 thinking/参数/输出原文 |
| A14 | 隐藏时完成/等待；点击并行会话通知 | 不抢焦点；点击准确会话；重试中不提前通知；拒绝通知权限不妨碍对话 |
| A15 | 建应用会话和独立终端会话；搜正文、重命名、置顶、删、重启续聊 | 只列应用会话；索引一致；删除确认；运行删除受控；用户产物保留 |
| A16 | 默认目录与用户选择目录分别创建文件；重启续聊后点击相对/绝对链接 | cwd 持久一致；默认应用/Finder 实际定位；附件和产物不因索引清理丢失 |
| A17 | 运行中关闭全部窗口，再托盘/快捷键恢复 | 菜单栏与进程仍在；任务继续；恢复当前会话正确 |
| A18 | 活跃任务退出先取消，再确认退出；另模拟 kill Pi/kill app | 取消后可用；确认后无应用所属 Pi 残留；重启中断且不自动重发 |
| A19 | 503 重试后成功、永久错误、主动 abort、下一轮成功 | 每轮终态正确；无提前完成通知；上一轮错误不污染下一轮 |

额外发布检查合并在上述场景内：正式构建 TS/Go 编译通过、后端 race 检查；macOS/CPU 支持范围据实际构建说明；本地 ad-hoc 可运行包与签名公证分发区分；长回复渲染不卡住输入；事件订阅窗口重建无重复监听；断网、休眠恢复不永久卡在 running。没有 Apple 签名资源时可交付本机可运行 .app，但不得标注已公证或对外分发已验收。
