work/final-real-tests.log 记录了此前全套真实验收：适配模块 2 项、正式 Engine 6 项全部通过，无视觉跳过。最后加入轻量历史读取后，另行重跑真实“普通对话→UI 命令→续聊→重启→继续对话”，14.52 秒通过。生产封版由主任务再执行全套检查；本报告不替代 macOS 专项验收。

## 最终关键修复

初审及追加测试发现的问题均已复验：SQLite 失败未回滚导致重试被吞；存储失败仍出队；启动期间停止无效；未知 action 误插入；裸 steer 在空闲时悬挂；纯 UI 命令永久 busy；路径规范化不一致；UI-only 历史序号错配；已结束提交仍占位导致队列不推进；排队后附件增大绕过预算；停止后晚到重试或交互复活。

RPC 内部增加事件 _sequence 和响应 _eventSequence，core 对账前等待先前事件消费，避免响应与事件通道解耦造成旧状态覆盖。这些字段不发给 Pi。

图片在发送前及实际读取时都按每条消息总计 16 MB 检查。适配器单 JSONL 帧上限 32 MB，异步待交付预算 64 MB 或 8192 条，超限终止所管理的进程并报告中断，不静默丢弃事件。

累计图片历史不再通过 get_messages 构成巨大响应。可选 HistoryReader 在 Pi 适配层只读已登记的受管 v3 JSONL 文件，逐条取文本和时间戳，丢弃图片、thinking、工具内容，按最新 leaf 的 parent 链生成显示投影。36 MB 累计图片夹具通过恢复测试，单条记录仍有 32 MB 上限。模型上下文、压缩和续聊完全由 Pi --session 处理，应用没有重建 Agent 上下文。

读取器检查受管路径、格式版本、重复 ID、父链缺失/循环；仅允许尾部未完成的一行被忽略，完整损坏记录报错。文件缺失使用专用错误，只有尚未形成 Agent 历史的新会话可以继续；已有历史保留显示记录并明确说明无法恢复上下文。

## 残留边界

SQLite 故障注入不等于真实断电，不提供跨模型提供商 exactly-once 执行保证。Pi v3 文件格式和 0.84.1 RPC 为验证基线，未来不兼容版本需重新核验；未知历史格式明确报错。第三方扩展产生超出 32 MB 的单条记录或帧仍会遇到明确容量限制。长期会话的文本索引内存、磁盘占用没有无限规模保证。

模型质量、任意文件格式、全部第三方扩展、系统休眠和 macOS 权限/签名不属于本后端报告的通过范围。基础图片识别测试证明真实图片交接，不代表任意视觉任务准确。
