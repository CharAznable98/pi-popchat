# macOS 图片粘贴失效修复

自定义应用菜单只注册了应用菜单和窗口菜单，遗漏标准编辑菜单，导致 Command-V 没有通过系统 paste: 命令交付给 WKWebView。生产修复是在主菜单中注册 Wails 的 EditMenu，恢复系统的剪切、复制、粘贴等标准命令；不截取按键读取剪贴板，也不添加第二套图片附件通道。

复现使用真实 NSPasteboard 和原生 Command-V 菜单/事件分发，贯穿 WKWebView paste 事件、React 附件上传、Go 持久化草稿。旧版本文字、PNG、TIFF 在主窗口和浮窗的六项均失败；修复后六项均成功，连同 WebView 就绪检查共 7 项通过。TIFF 经 WKWebView 转成 PNG，图片草稿中恰有一个 image/png 附件。

测试使用隔离临时会话及合成的 2×2 图片，原剪贴板只暂存在内存，结束时恢复；如果外部应用改变剪贴板，则不覆盖新内容。测试必须等待目标会话标题完成渲染且输入框拥有焦点，再触发粘贴，避免事件投给上一个会话的假失败。报告仅记录长度、数量和格式，不保存用户剪贴板内容。

复跑：先退出空闲 Pi Popchat，构建后执行 `sh scripts/check-native-clipboard.sh`。脚本严格检查本次 JSON 七项均通过，不能只根据进程退出码判断。

`sh scripts/test.sh` 通过，包括 28 项前端测试、Go 核心/适配器/桌面竞态检查和生产前端构建。本次未向真实模型发送剪贴板内容。

复跑结果：第一轮7/7通过；第二轮主窗口文字粘贴时没有焦点而失败，其余6项通过，其中两窗口的PNG/TIFF四项均通过。保留第二轮原始失败报告，不计为连续两轮全通过。
