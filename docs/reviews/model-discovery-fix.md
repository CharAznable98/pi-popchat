# 首次打开误报没有可用模型

原因：前端以 models.length === 0 直接显示配置提示，没有区分尚未查询、查询中、查询失败和查询成功但为空。新建会话未主动刷新；已有进程的 Refresh 也只确保连接存在。

修复：会话模型元数据增加独立状态和错误信息，查询成功后才可显示空列表配置提示；重启重置查询状态。主窗口新建会话自动触发发现；现有的启动、选中、浮窗打开路径保持自动获取。手动刷新在已有 Pi 连接上重新查询模型列表，不重启进程、不发送对话。模型查询失败不会改变会话执行状态。

验证：
- 修复前执行前端“首次模型信息尚未返回时显示加载状态”测试，得到错误配置提示，断言失败；修复后通过。
- 28 项前端测试通过（4 项状态测试、24 项组件测试），包括加载、真实空列表、失败重试。
- sh scripts/test.sh 通过，包括 Go 核心、适配器、桌面竞态检查及前端生产构建。
- 真实 Pi 在隔离临时会话中首次发现及已有连接刷新均返回 398 个模型；未向模型发送消息。
- 生产应用构建成功，退出空闲旧版后重启，未手动刷新即可看到模型选择器。

回归覆盖：TestModelsDiscoveryLifecycleAndRefresh、TestModelRefreshFailureDoesNotFailConversation、TestAcceptanceRealPiModelDiscovery。模型发现状态独立于任务状态，避免以后再次用空列表推断加载结果。
