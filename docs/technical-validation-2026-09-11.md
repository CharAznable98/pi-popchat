## 2. Pi 标题：可接入，存在首次落盘边界

Pi 协议检查共 23 项通过（原有 17 项加本次 6 项）。本次新增断言覆盖以下事实：

| 实测能力 | 结果及实现影响 |
|---|---|
| RPC 设置标题、事件和状态读取 | `set_session_name` 成功后产生 `session_info_changed`；`get_state.sessionName` 一致。Pi 会清除首尾空白并将换行替换为空格，应采用其规范化结果 |
| 空标题与扩展清除标题 | 空白 RPC 改名失败，保留原名；扩展 `pi.setSessionName("")` 可以清除标题，事件的 `name` 与状态的 `sessionName` 随之缺省。必须处理缺省为清除，不能忽略事件 |
| 关闭后读取与重启 | Pi JSONL 最后一条 `session_info` 提供当前标题，空字符串表示清除；重启后结果一致。无需为历史标题启动模型请求 |
| 尚无助手消息时改名 | RPC 返回成功且内存可读，但会话文件尚不存在；首条助手消息到来后才连同标题落盘 |

最后一项由真实进程复现，并与 Pi `SessionManager._persist()` 核对。**RPC 改名成功不始终等于持久化完成**。已有持久化会话的改名/重启验证通过；仅在应用落盘、Pi 尚无助手记录的会话仍有风险。用户已确认：Pi 会话尚未持久化前禁用改名并说明原因，落盘后恢复入口；不用应用自有标题覆盖此缺口。

接入建议：在 `internal/agent/pi` 内提供标题状态与受管历史文件的只读投影，在 core 中保存可重建的展示/搜索缓存，沿用现有事件序号协调避免旧快照覆盖较新的改名事件。读取历史只限应用登记的 Pi 会话路径，复用现有路径校验。保留用户显式改名入口，不自动写入兜底标题或旧应用标题。

## 3. 过程记录：事件足够，历史耗时需要应用保存

实际工具事件字段如下：

| 事件 | 可用字段 |
|---|---|
| `tool_execution_start` | `toolCallId`、`toolName`、`args` |
| `tool_execution_update` | `toolCallId`、`toolName`、`args`、`partialResult` |
| `tool_execution_end` | `toolCallId`、`toolName`、`result`、`isError` |

实测内置 `read` 可从 `args.path` 获取具体对象，通过 `toolCallId` 对齐开始和结束；合成扩展工具同样有开始、更新、结束事件。Pi 没有统一的“读取文件/搜索主题”语义字段。建议先映射已知工具，未知扩展保留工具名和状态，无法识别对象时不猜测，不直接展示全部参数。尤其 `bash` 只表示命令执行，不能把任意脚本可靠推断成“搜索”。

过程状态由 core 接收事件时保存；界面按连续同类动作分组，保留独立工具 ID 和状态。上述事件不含完整时间戳，开始时间和耗时要在客户端采集。Pi 历史有 tool call/result，可用于有限恢复，但没有完整工具开始事件和实时更新记录，无法还原真实运行耗时。因此要兑现“历史可查看”，需持久化应用自己的过程投影，不回写 Pi 上下文。

新增失败测试表明：工具 `isError=true` 后，助手仍可正常回复并结束。工具失败、用户停止、进程中断、整轮最终结果必须分别处理。现有 `agent_settled` 和自动重试判断继续沿用。没有新事件时只能展示等待及耗时，不假定正在搜索或思考。

本次探针进程 `AXIsProcessTrusted()` 为真，没有触发权限申请。**此结果不代表正式 Pi Popchat 应用已获授权**，签名与实际应用身份需要单独验收。监听注册成功也不代表真实鼠标划词事件已验收；当前探针程序设置选区，没有验证物理拖选、双击选词、键盘选择事件。

推荐路径是监听鼠标选词结束，再读取来源应用当前选区，捕获文本后用非激活工具条展示；不要在读取前激活回答窗口，避免丢失来源选区。工具条按钮消费该次捕获内容，随后进入现有回答浮窗。辅助功能调用需要超时和过期请求丢弃，不能阻塞主线程或把旧选区绑定到新按钮动作。

Apple 的[事件监听说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)区分全局与本应用监听：全局监听不接收本应用事件；实现应用内划词需补本地事件路径。键盘事件监听有辅助功能权限要求。选区 API 的实际可用性以本次子进程测试及 SDK 定义为依据。

尚未通过的范围：Chrome/Electron/飞书/编辑器/PDF 的真实控件；无权限与权限撤销；安全输入/不支持选区的控件；点击工具条时跨进程焦点与原选区；工具条收起及陈旧内容保护；跨屏坐标转换和全屏覆盖。3 屏环境只记录了屏幕数量，不等于跨屏验收。

建议取词失败时不显示工具条，权限缺失时在设置页说明授权路径；不使用模拟复制、剪贴板或 OCR 扩大读取范围。该降级方案仍待需求确认。

## 5. 复用现有浮窗与模板的实施边界

代码核查发现 `Engine.NewSession()` 会复用全局未发送草稿；不能用“NewSession 然后 Send”实现划词，否则可能消耗原草稿。需要 core 提供独立“创建正式会话并保存首条消息”的操作，复用持久化和投递调度，保持已有草稿不变。该操作需增加并发/失败行为与 race 测试，不能依赖前端连续调用保证原子性。

桌面已有 `showPanelOn()` 和鼠标选屏逻辑可复用；新入口应显式打开新会话，不调用会将已可见浮窗收起的快捷键 toggle。还需避免 `PanelShown()` 的超时换会话逻辑覆盖本次已指定的新会话。这是共用窗口入口的重构，不增加第二套回答浮窗。

模板变量没有 Pi 专有依赖，可在应用本地按单次扫描替换，然后调用既有 Agent prompt。时间在点击时冻结，替换文本不再次展开；未知变量原样保留。没有 `{{text}}` 不补内容，若最终生成空请求，沿用有效提交校验，不凭空创建历史。

本机系统语言实测为 `zh-Hans-CN`，实现不能假定只会返回 `zh-CN`；系统时区为 `Asia/Shanghai`。语言标记需保留脚本/地区信息，判断同语言时不能只做完整字符串相等。

默认翻译的“无备用语言时先选目标”仍有前置条件：须判断选中文字已是英语。Pi 没有提供不执行对话的通用文本语言检测 RPC，本次没有验证本地语言识别质量。可以将通常的翻译规则写入默认提示词，但不能宣称这就实现了发送前语言选择。实施前需确定并验证本地语言检测及短词/混合语言的歧义处理，或者重新确认目标语言选择交互。
